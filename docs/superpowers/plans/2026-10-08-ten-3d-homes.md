# Ten 3D Homes Implementation Plan

> For agentic workers: use superpowers:executing-plans to implement this plan in the existing isolated feature checkout.

**Goal:** Make all ten homes selectable, navigable three-dimensional spaces supporting the existing residents and pets.

**Architecture:** Pure scene definitions and save normalization feed a single active Three.js world. A shell builder supplies distinct architecture; the existing furniture, animation, controls and activity systems use a common floor-height function. Journey content stays available through the 3D interface and secondary journal.

**Tech stack:** Existing Three.js 0.165, JavaScript, Python build, Node test runner, Playwright.

**Spec:** `docs/superpowers/specs/2026-10-08-ten-3d-homes.md`

## Constraints

- Preserve `cloudhome.v3`, existing pet IDs, currency, residents, letters and furnishings.
- Preserve standalone offline HTML with all assets and license notices embedded.
- Use shared geometry/material caches and release only scene-owned resources.
- Room switching captures the current furniture before rebuilding, including switches within the existing 300 ms save debounce.
- A raised floor is traversable through stairs; a cliff is not a valid navigation shortcut.

## Review focus

- Legacy saves: existing purchases and coordinates survive migration.
- Interrupted seated/social/minigame actions: switching rooms leaves no stale host or mount.
- Upper-floor activities: seating offsets and actors use the furniture's floor elevation.
- Fast repeated switches: independent layouts persist and old geometry is released.
- Mobile/keyboard selection: modal focus works and the primary view remains an interactive canvas.
